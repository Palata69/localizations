# Локализация

Все тексты, которые видят игроки: сообщения в чате, меню, предметы, табло, тайтлы, кик-экраны.
Пишутся один раз на русском (основной язык), в едином стиле и в hex-цветах.

Публичный источник: https://github.com/Palata69/localizations, ветка `main`.
Core скачивает архив при запуске и по `reloadlanguages @all`, проверяет тексты и
рассылает их прокси и игровым серверам. Последний корректный архив сохраняется в
`localizations-cache.zip` рядом с core. Если GitHub недоступен или тексты содержат
ошибки, используется кеш, затем локальный каталог или встроенная копия в jar.

Источник можно изменить через `MINSTER_LOCALIZATION_URL` / `-Dlocalization.url`,
а путь кеша — `MINSTER_LOCALIZATION_CACHE` / `-Dlocalization.cache`.
Значение URL `off` включает загрузку только из локальных источников.
Обновление текстов: изменить файлы этого репозитория, отправить изменения в `main`,
затем выполнить `reloadlanguages @all` в консоли core или перезапустить core.

## Быстрый старт

**Переименовать сеть** — поменять `name` в [`brand.yml`](brand.yml) (и адреса, если нужно), затем в консоли ядра:

```
reloadlanguages @all
```

Ядро перечитает каталог `localizations/` и разошлёт его всем серверам и прокси — новое имя появится
везде за пару секунд. Меню, табло и предметы, которые уже открыты, обновятся при следующей отрисовке.

**Поправить текст** — найти ключ (поиск по `ru/`), изменить, выполнить ту же команду.

**Где ядро берёт файлы.** Каталог `-Dlocalization.dir` (по умолчанию `./localizations` рядом с `Core.jar`);
если его нет — копия, собранная в jar. Серверы и прокси получают локализацию от ядра при подключении,
а до этого пользуются копией из jar.

## Файлы

```
localizations/
  brand.yml          название сети, домен, сайт, магазин, соцсети
  palette.yml        цвета-роли и шаблоны ({ok}, {err}, {brand}...)
  ru/
    core/            ядро и прокси: вход, чат, друзья, группы, наказания, жалобы, команды...
    base/            общее для игровых серверов: игрок, предметы, меню, донат, суффиксы...
    lobby/           хаб и лобби: выбор режима, профиль, табло, голосование...
    game/            мини-игры: режимы, победа и поражение, смерти, команды, наблюдатели...
    staff/           только для персонала: стафф-чат (chat.yml) и уведомления (notifications.yml) —
                     вход персонала, наказания, жалобы, слежка через /tunnel
    words.yml        склонения слов («монета», «монеты», «монет»)
    vanilla.yml      названия предметов, блоков, эффектов и существ Minecraft (генерируется)
  en/                переводы (пока пусто — игрок видит русский текст)
  tools/
    generate_vanilla.py   пересобрать vanilla.yml из официального ru_ru.json Mojang
    dynamic-keys.txt      ключи, которые код собирает сам (для проверки)
```

Деление на каталоги и файлы — только для удобства: ключ ищется во всех файлах языка сразу,
поэтому один и тот же ключ в двух файлах — ошибка. `vanilla.yml` руками не правится:
`python localizations/tools/generate_vanilla.py`.

Формат файла — YAML «ключ: текст». Многострочный текст — списком:

```yaml
party_invite_received:
  - "{line}"
  - "{info}<accent>%player%</accent> приглашает вас в группу"
  - "<muted>Нажмите, чтобы принять, или напишите <primary>/party accept %player%"
  - "{line}"
```

Пишите значения в **двойных кавычках**, если в тексте есть `:` `#` `{` `[` или текст начинается с `<`.
Внутри двойных кавычек обратная косая черта удваивается: буквальная скобка — `"\\<player>"`, `"\\{"`.
В одинарных кавычках — как есть: `'\<player>'`.

## Разметка

Подмножество [MiniMessage](https://docs.advntr.dev/minimessage/format.html). При загрузке
превращается в обычную строку с цветами `§x§R§R§G§G§B§B`, поэтому работает везде: в чате, на предметах,
в табло, в меню, на прокси.

| Запись | Что делает |
|---|---|
| `<primary>текст</primary>` | цвет-роль из палитры (основной способ) |
| `` `<i>` `<u>` `<st>` `<obf>` | жирный, курсив, подчёркнутый, зачёркнутый, «шум» |
| `</primary>`, `` | закрыть тег; `</>` — закрыть последний открытый |
| `<reset>` | закрыть все теги |
| `<gradient:brand_from:brand_to>текст</gradient>` | градиент по буквам, цвета — роли или `#hex`, можно больше двух |
| `<#9D8CFF>` | произвольный цвет — **только в исключительных случаях** |
| `{server}` `{domain}` `{site}` `{store}` `{discord}` `{telegram}` | значения из `brand.yml` |
| `{server\|upper}`, `\|lower`, `\|capital` | то же в верхнем / нижнем регистре / с заглавной |
| `{ok}` `{err}` `{warn}` `{info}` `{brand}` `{dot}` `{arrow}` `{line}` `{logo}` | шаблоны из `palette.yml` |
| `{rank:premium}` | название ранга его цветом |
| `{@другой_ключ}` | вставить текст другого сообщения (`{@ключ\|lower}` — со строчной) |
| `%player%` | значение, которое подставит код |
| `\<` `\{` | буквальные `<` и `{` (в YAML с двойными кавычками — `\\<`, `\\{`) |

Правила:

- Сообщение с разметкой начинается цветом `text` — писать его в начале не нужно.
- Строка **без единого тега** выводится без цвета: это фрагмент (слово, название, единица), который код
  вставляет в другую строку, и он берёт цвет места вставки. Поэтому названия предметов, строки описания
  и тайтлы всегда начинайте с роли (`<primary>`, `<muted>`...): без цвета Minecraft покажет их курсивом.
- Незакрытые теги закрываются сами в конце строки: `<muted>пояснение` — нормально.
- После `%значения%` цвет восстанавливается сам: если в значение пришёл цветной ник, остаток строки не «перекрасится».
- `%значение%` нельзя ставить внутрь `<gradient>`: длина заранее неизвестна.
- Текст в угловых скобках кириллицей — не тег: `/party invite <ник>` выводится как есть.
  Латиницей — экранируйте: `"\\<player>"` (или `'\<player>'` в одинарных кавычках).
- **Нельзя** писать старые коды `§a`, `&a`. Проверка сборки их не пропустит.

## Палитра

Цвета задаются **ролью**, а не кодом — тогда стиль всей сети меняется в одном месте, в [`palette.yml`](palette.yml).

| Роль | Цвет | Для чего |
|---|---|---|
| `text` | `#E6E6F0` | основной текст; цвет по умолчанию |
| `muted` | `#A3A3B8` | пояснения, подсказки, описания предметов |
| `dark` | `#6B6B80` | рамки, разделители, скобки, «—» |
| `primary` | `#9D8CFF` | акценты бренда: названия разделов, заголовки, **команды** |
| `accent` | `#FFD166` | **значения**: ники, числа, валюта, время, названия режимов и предметов |
| `success` | `#6EE7A0` | успех, «доступно», «включено» |
| `error` | `#FF6B7A` | ошибки, запреты, «недоступно», «выключено» |
| `warning` | `#FFB454` | предупреждения, «осторожно», «скоро истечёт» |
| `info` | `#7CC7FF` | справка, нейтральные уведомления |
| `link` | `#7CC7FF`, подчёркнутый | ссылки и кликабельный текст |
| `brand_from` → `brand_to` | `#9D8CFF` → `#6FB6FF` | градиент названия сети |
| `rarity_none` … `rarity_legendary` | серый, светло-серый, голубой, фиолетовый, оранжевый | редкость предметов и кейсов |

Шаблоны:

| Шаблон | Вид | Когда |
|---|---|---|
| `{ok}` | ✔ зелёная галочка | действие выполнено |
| `{err}` | ✖ красный крестик | ошибка, отказ |
| `{warn}` | ⚠ оранжевый знак | предупреждение |
| `{info}` | ✦ фиолетовая звезда | уведомление, справка |
| `{staff}` | **Персонал** ┃ оранжевым | уведомления только для персонала (перед `{info}`/`{warn}`) |
| `{brand}` | **MINSTER** ┃ градиентом | от имени сети: объявления, рассылки |
| `{logo}` | **MINSTER** градиентом | заголовок табло, тайтл, кик-экран |
| `{dot}` | • | пункт списка |
| `{arrow}` | » | «переход», «далее» |
| `{line}` | ──────── | верх и низ многострочного сообщения |

## Типы сообщений

Каждый тип — в одном виде по всей сети. Примеры ниже — эталон.

**Успех**
```yaml
friend_added: "{ok}<accent>%player%</accent> теперь у вас в друзьях"
```

**Ошибка**
```yaml
player_not_found: "{err}Игрок <accent>%player%</accent> не найден"
```
Объясняйте, что делать: `{err}Вы уже в группе. Выйти — <primary>/party leave`

**Предупреждение**
```yaml
group_expires_soon: "{warn}Ранг {rank:premium} закончится через <accent>%time%"
```

**Уведомление**
```yaml
party_member_joined: "{info}<accent>%player%</accent> вступил в группу"
```

**Использование команды.** В ключе `_usage` — **только аргументы** (`muted`, необязательные в `[ ]`):
саму команду (`/party invite`) код подставляет сам перед ними. Шаблоны строк — `command_usage` и `command_help_row`,
в них `%usage%` — команда с аргументами (красим её `primary`).
```yaml
command_party_invite_usage: "<muted><ник>"
command_party_invite_description: "пригласить игрока в группу"
command_usage: "{info}Использование: <primary>%usage%"
command_help_row: "{dot}<primary>%usage%</primary> <dark>—</dark> <muted>%description%"
```

**Список с заголовком**
```yaml
friend_list_header:
  - "{line}"
  - "<primary>Друзья <dark>(<accent>%count%</accent>/<accent>%limit%</accent>)"
friend_list_entry: "{dot}<accent>%player%</accent> <dark>—</dark> <success>в сети"
friend_list_footer: "{line}"
```

**Запрос и приглашение** — кто, что, как ответить:
```yaml
friend_request_received: "{info}<accent>%player%</accent> хочет добавить вас в друзья. Принять — <primary>/friend add %player%"
```

**Объявление от имени сети**
```yaml
alert_format: "{brand}%message%"
```

**Кик-экран** — логотип, причина, подробности, что делать:
```yaml
ban_screen:
  - "{logo}"
  - ""
  - "<error>Вы заблокированы"
  - "<muted>Причина: <text>%reason%"
  - "<muted>Осталось: <accent>%time%"
  - ""
  - "<muted>Обжаловать: <link>{site}"
```

**Тайтл и action bar** — коротко; заголовок цветом, подзаголовок — `text` или `muted`:
```yaml
game_winner_title: "<success>ПОБЕДА"
game_winner_subtitle: "<muted>Вы заняли <accent>1</accent> место"
```

**Табло** — заголовок `{logo}`, строки «подпись — значение», внизу домен:
```yaml
hub_board_title: "{logo}"
hub_board_rank: "<muted>Ранг: %rank%"
hub_board_coins: "<muted>Монеты: <accent>%coins%"
hub_board_footer: "<primary>{domain}"
```

**Предмет и меню** — название `primary` (или цвет редкости), описание `muted`, внизу действие:
```yaml
lobby_selector_item_name: "<primary>Выбор режима"
lobby_selector_item_lore:
  - "<muted>Все игры сети"
  - "<muted>в одном меню"
  - ""
  - "<accent>ПКМ</accent> <dark>—</dark> <muted>открыть"
```
Заголовок окна (инвентаря) — `<dark>` или `<primary>`, без значков.

**Персоналу** — стафф-чат и уведомления лежат отдельно, в `ru/staff/`. Уведомление начинается с шаблона
по смыслу (`{info}` — событие, `{warn}` — наказание или подозрительное действие), кто сделал и с кем — `accent`:
```yaml
mute_broadcast: "{warn}<accent>%name%</accent> выдал мут <accent>%target%</accent> на <accent>%time%</accent>. Причина: %reason%"
```
Новое сообщение, которое код рассылает через `broadcastStaff`, кладите туда же.

**Всплывающая подсказка** (hover) — `muted` с значениями `accent`, построчно.

## Тон и текст

- Обращаемся на **«вы»** со строчной: «у вас нет прав».
- Коротко. Одна мысль — одно сообщение. Без капса (кроме тайтлов и подписей рангов).
- Однострочные сообщения — **без точки** в конце. «!» — только для поздравлений.
- Буква **«ё»** обязательна: «вошёл», «ещё».
- Кавычки — «ёлочки».
- Числа — цифрами, с пробелом между разрядами: `12 500`. Время — словами: «5 минут», «2 ч 30 мин» (подставляет код).
- Ники, числа, время, названия — `accent`. Команды — `primary`. Не красьте целые фразы.
- Значки — только из шаблонов (`{ok}`, `{err}`...). Эмодзи и псевдографику не придумывайте.
- Не пишите название сети буквами — только `{server}`, адреса — `{domain}`, `{site}`...
- Род: если пол неизвестен — безличная форма («Игрок … вошёл в игру» → «<accent>%player%</accent> в игре»)
  или мужской род.

## Ранги

Ранги и всё их оформление — **в коде**, enum
[`Group`](../core/core-base/src/main/java/by/minster/core/base/data/permission/Group.java):
цвет `RRGGBB`, название («Premium») и подпись обычным начертанием в префиксе (`PREMIUM`). Префикс — подпись цветом ранга,
затем ник тем же цветом: **PREMIUM** Ник.

В тексте ранг пишется через `{rank:имя}` — название его цветом: «Доступно с {rank:premium}».
Если ранг приходит из кода, он подставляется как `%group%` или `%group_name%` — уже цветной.

Табличка над головой и свечение в Minecraft бывают только 16 цветов — для них берётся ближайший к цвету ранга.

## Ключи

- Только **нижний регистр**, слова через `_`: `раздел_предмет_действие` — `party_invite_sent`, `friend_list_header`.
- Раздел = файл: ключи `party_*` — в `ru/party.yml`.
- Не переименовывайте ключи без правки кода: ключ ищется в коде по имени.

Ключи, которые код собирает сам:

| Шаблон | Пример |
|---|---|
| `command_<команда>_usage`, `command_<команда>_<подкоманда>_usage` | `command_party_invite_usage` |
| `command_<команда>[_<подкоманда>]_description` | для команд со справкой |
| `<ключ>_single` / `_onemore` / `_plural` | окончания: «1 бан», «2 бана», «5 банов» |
| `noun_<слово>_<род>_<падеж>[_multi]`, `adjective_…` | `ru/words.yml`, склонения |
| `report_reason_<причина>`, `rarity_<редкость>`, `setting_<настройка>_name`... | значения перечислений |

Ключи, которые задают **плагины режимов** (не из этого репозитория), пишутся в их собственных файлах
по тем же правилам: `request_<тип>_*`, `category_<id>_description`, `<статистика>_quest`, `rule_<номер>`.

## Как добавить язык

1. Добавить язык в enum `Language` (`core-base/.../language/Language.java`): название, короткое имя.
2. Создать каталог `localizations/<короткое имя>/` и переводить файлы из `ru/` с теми же ключами.
3. Чего нет в переводе, игрок увидит на русском.

## Проверка

```bash
cd core
./gradlew :core-base:test
```

Тесты собирают всю локализацию и падают, если:

- в разметке ошибка (неизвестный тег или переменная, лишний закрывающий тег);
- ключ используется в коде, но его нет в `ru/`;
- в тексте нет `%значения%`, которое передаёт код;
- встречаются старые коды `§` или `&`;
- ключ повторяется или написан не в нижнем регистре.

Во всех текстах сети используется обычное начертание: жирные теги и роль `bold` не добавляем.
